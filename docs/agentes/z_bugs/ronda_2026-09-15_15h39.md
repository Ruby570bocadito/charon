## Defectos encontrados y corregidos durante el desarrollo

1. **Honestidad de datos en el JSON de entradas de configuración (BAJA →
   CORREGIDA)**: las entradas `X-CACHECONF:` que kinit escribe guardan sus
   campos de tiempo y ticket a 0; la primera versión del JSON habría
   expuesto "1970..." como authtime/endtime reales. Corregido: para
   entradas de configuración el JSON expone `null` en `session_etype`,
   `session_etype_name`, `ticket_kvno`, `ticket_sname`, `authtime`,
   `starttime`, `endtime`, `renew_till` y `seconds_left`, y `expired`
   ancla a false. Test nuevo que fija el contrato (nulls verificados).
2. **Tipo del estado de vigencia en `print_ccache` (compilación)**: los
   dos brazos del if/else devolvían `BoldDisplay<FgColorDisplay<Red>>` vs
   `FgColorDisplay<Green>` (E0308). Corregido con `.to_string()` en ambos
   brazos.
3. **Préstamo de temporal en el índice de credencial (E0716)**:
   `format!("[{i}]").dimmed()` tomaba prestado un String temporal.
   Corregido enlazando el String antes de colorear.
4. **Helper de test con offset negativo recortado**: `in_secs.max(0)`
   hacía imposible probar una credencial caducada (endtime = ahora
   exacto). Corregido: aritmética en i64 y cast final; el test de
   caducidad ahora ejercita −3600 s reales.
5. **Doc comment fuera de lugar (`///` dentro de función)**: habría
   disparado `unused_doc_comments` con `-D warnings`. Corregido a `//`.

## Seguridad — revisión del código nuevo

- **Material sensible**: `charon ccache` expone el enctype de la clave de
  sesión (id numérico) y NUNCA los bytes de la clave — misma garantía que
  `keytab` (que no imprime claves). Nota de material sensible repetida en
  la salida.
- **Permisos**: el aviso de ficheros con claves en claro se generalizó a
  `warn_lax_secret_file_perms(path, what)` y cubre keytab Y ccache; mensaje
  idéntico en espíritu (stderr, aviso, no error — leer es legítimo).
- **Parser acotado**: el comando reutiliza `CcacheFile::parse` (lecturas
  con tope contra ficheros hostiles) y `ticket_of` con manejo de error —
  un ccache corrupto produce error controlado, nunca panic (tests de
  truncado lo verifican).
- **Reloj local**: la vigencia se calcula contra el reloj del analista;
  la limitación está documentada en el código (inherente a herramienta
  offline, igual que klist).
