## Decisiones tomadas

- El formato ccache se valida CONTRA `klist`/`kinit` reales de MIT 1.21.3
  (interoperabilidad demostrada, no "esperamos que sea correcto"): antes de
  escribir código se captura un ccache de referencia con `kinit -c` y se
  contrasta el layout byte a byte; después el nuestro se lee con `klist -c`
  y se renueva con `kinit -R -c`.
- S4U2Proxy se construye sobre el bloque común `build_pa_tgs_req` ya
  refactorizado en la Ronda 2 (menos superficie nueva); la clave del
  servicio destino para la prueba del PAC viene de su contraseña de lab
  (los servicios reales usan keytab — queda como posible mejora futura,
  no como deuda de esta ronda).
- La suite de integración de S4U2Proxy depende de un fixture del lab
  (principales svc-api/svc-db): si no existen, el test avisa con mensaje
  claro y termina limpio (misma política que `kdc_available`); el setup
  queda scriptado y documentado para reproducirlo.
- No se toca el dominio crypto ni el codec DER: ronda aditiva de protocolo
  y formato de fichero, sin rediseños.
