## Decisiones tomadas

- **La verificación de esta ronda es "lab desde cero"**: se paró el KDC, se
  borró la BD y se ejecutó el script corregido completo (compilación saltada,
  BD + principals + arranque + smoke test) antes de correr la suite. Es el
  estándar mínimo para cualquier ronda que toque el lab: el script versionado
  es la única fuente de verdad del entorno.
- El parser de keytab sigue el patrón del ccache (Ronda 3): lecturas acotadas
  sin panics, errores con offset, y el formato documentado en el módulo con
  referencia a las líneas de `kt_file.c` que lo definen. Charon LEE keytabs
  pero no los ESCRIBE: `ktutil` existe, y un escritor sin llamador sería
  código muerto.
- Los fixtures de keytab son de MIT (`ktutil addent`), no hechos a mano: el
  test unitario parsea bytes que MIT escribió de verdad. El que lleva la clave
  de jdoe del lab usa una contraseña ya documentada en el repo (desechable por
  diseño); el otro, una contraseña de prueba sin relación con el lab.
